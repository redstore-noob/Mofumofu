# 第一章：快速建立开发环境

本章带你从零搭好 Mofumofu 插件的开发环境，并跑通"改代码 → 热重载看效果"的循环。

## 1. 你需要准备什么

| 依赖 | 版本 | 说明 |
|---|---|---|
| .NET SDK | 10.0 或更高 | `dotnet --version` 能看到 10.x 即可 |
| IDE | Rider / VS2026 / VSCode | 随意，能打开 .slnx 就行 |
| Mofumofu 源码 | main 分支 | `git clone https://github.com/redstore-noob/Mofumofu` |

不需要安装 Avalonia 模板——插件就是普通类库项目，用 `dotnet new classlib` 起手即可。

## 2. 认识解决方案

```
Mofumofu/
├── Mofumofu.ExtensionAPI/        ← 插件 API 契约库（你唯一需要引用的项目）
├── Mofumofu.Launcher/            ← 启动器本体（宿主，跑起来用的）
├── MofuCore/                     ← 启动器内核（插件不直接引用）
└── NekoSolo/                     ← 单包安装器（与插件开发无关）
```

**插件只引用 `Mofumofu.ExtensionAPI`，不要引用启动器本体或 MofuCore。**
契约库里已经带好了 `Avalonia 12.1.4` 的编译期引用（`ExcludeAssets="runtime"`），
也就是说你写界面用的 `Control`、`TextBlock` 等类型由宿主在运行时提供——
你的插件 DLL 里不会打包 Avalonia，几十 KB 就是全部体积。

## 3. 插件项目模板

新建一个类库项目，csproj 长这样：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Avalonia" Version="12.1.4" ExcludeAssets="runtime" />
  </ItemGroup>
  <ItemGroup>
    <ProjectReference Include="..\Mofumofu.ExtensionAPI\Mofumofu.ExtensionAPI.csproj" />
  </ItemGroup>
</Project>
```

> `ExcludeAssets="runtime"` 是关键：它保证 Avalonia 的 DLL 不会被复制进你的插件输出目录。
> 运行时宿主会和插件共享同一份 Avalonia，类型不会分裂。

## 4. 插件放在哪里、怎么调试

启动器是**便携式**布局，插件目录在程序目录旁边：

```
（启动器所在目录）/
└── Mofumofu/
    ├── config/     settings.yaml 等配置
    ├── plugins/    ← 插件目录
    │   └── my-plugin/
    │       ├── plugin.yaml     ← 开发态清单（名字随意，见第二章）
    │       └── MyPlugin.dll    ← 编译产物（DLL 名不限，打包发布时才改名 extension.dll）
    └── logs/       plugins.log 插件日志
```

**推荐调试循环**：

1. `dotnet build -c Debug` 你的插件项目
2. 把输出 DLL 复制到 `Mofumofu/plugins/my-plugin/`
3. 启动器里打开 插件 页，点右上角**重载按钮**——插件热加载，不用重启启动器
4. 改代码 → 重新 build → 再点重载，循环往复

日志在 `Mofumofu/logs/plugins.log`，`context.Log(...)` 写的内容和宿主的装卸记录都在里面。

## 5. 热加载的边界（重要）

插件运行在**可回收的 AssemblyLoadContext** 里，停用/卸载/重载时宿主会：

- 撤销插件注册过的一切（页面、组件、样式、壁纸接管……都通过注册时返回的 `IDisposable`）
- 卸载插件的程序集，**尽力**让它被垃圾回收

所以插件作者要遵守两条纪律，否则旧版本可能滞留到重启：

- **控件里别起停不下来的后台线程/定时器**。如果必须用 `DispatcherTimer`，
  请像示例时钟一样在 `DetachedFromVisualTree` 里停掉它
- 别把插件类型挂进静态缓存（比如订阅别人的静态事件不退订）

就算违反了也不会崩——宿主会提示"该插件的旧版本将在重启启动器后完全释放"，
但热重载就会退化成"重启才生效"，调试体验变差。

## 6. 常见问题

- **Q：编译报找不到 Avalonia 类型？**  
  A：检查 csproj 是否加了 `ExcludeAssets="runtime"` 的 Avalonia 引用，以及目标框架是不是 `net10.0`。
- **Q：插件页显示"不兼容"？**  
  A：清单里的 `apiVersion` 高于宿主支持的版本会拒绝加载，见第三章的版本约定。
- **Q：调用 API 抛 `PluginPermissionException`？**  
  A：在清单 `permissions:` 里声明对应权限区，且玩家没在插件页把它关掉。权限区表见第三章。
